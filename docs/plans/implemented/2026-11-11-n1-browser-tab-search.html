Browser tab search

Make QuickSwitch find and switch to tabs in Chrome, Edge, Brave, Firefox and other browsers, read through UI Automation (approach 1).

Created 2026-11-11 · Status: implemented, shipped in 0.4.0 (2026-11-11). The same release also added type filters, web search and a Settings view (see README §2) · Target version: 0.4.0

1. Summary

  • Every open browser tab becomes a search result with the badge Browser tab. Typing searches tab titles and the browser name. Enter selects the tab and brings its window to the front.
  • Tabs are read with UI Automation, the same Windows accessibility API that already switches Explorer tabs. Nothing has to be installed in the browser.
  • With nothing typed, each browser window still shows as one row (its current tab), so 40 open tabs don't flood the list. All the other tabs appear as soon as you type.
  • Browser tabs are read on the existing background worker, after Explorer tabs. The popup still opens at once, and browser tabs join the list a moment later.
  • The browser only shows titles to UI Automation, not URLs, so URL search is out of scope.
  • Work starts with a test run (§5): a small diagnostic program that prints each browser's tab strip and tries switching. Its results decide the details of §6 and whether Firefox is in the first release.

2. What the user gets

2.1 Rows

Part of the rowContent
TitleThe tab's title as shown on its tab, cleaned of state the browser adds for screen readers (e.g. “Audio playing”, “Memory usage – 1.2 GB”, “Pinned”).
Grey textThe browser's name: Chrome, Edge, Brave, Firefox, …, plus the profile name when the window title shows one (Edge does, e.g. Edge · Work).
BadgeBrowser tab, in a new pink colour (#ec4899) next to Window (blue), Explorer tab (amber) and Folder (green).

2.2 Matching and order

  • Matched like windows today: every typed word must match the title or the browser name, in any order. edge pull finds the Edge copy of a pull-request page only.
  • Nothing typed: each browser window stands as one row for its current tab, in window order, like Explorer windows today. The other tabs are searched but not listed. This works like remembered folders, which are also only listed once you type.
  • Something typed: all tabs take part. Ties are broken as now: recent picks first, then window order, then tab-strip order.

2.3 Switching

  • Enter or a click selects the tab in its window's tab strip, restores the window if it was minimized, and brings it to the front. The popup closes.
  • If the tab or window has gone, the footer says so (“The tab “…” is no longer open.”) and the row is removed. The popup stays open.
  • While switching, the footer shows “Switching tab…”, as it does for Explorer tabs.

2.4 Not covered

  • URLs (only the active tab's URL is visible, and only in its address bar).
  • Tabs inside a collapsed tab group, if the browser leaves them out of UI Automation (the test run will show). They come back once the group is expanded.
  • Windows on other virtual desktops (skipped today for all windows).
  • Electron apps (VS Code, Slack, Discord, Teams). They share Chrome's window class but are not browsers, and they stay normal window rows.

2.5 Windows Terminal tabs (added)

  • Windows Terminal (CASCADIA_HOSTING_WINDOW_CLASS, WindowsTerminal.exe) is one more row in the §4.1 table with its own engine. Its tabs are read and switched by the same code as browser tabs.
  • Rows get the badge Terminal tab (teal, #14b8a6) and the grey text Terminal. Shell titles repeat a lot (“PowerShell”), so a repeated title adds its tab number: Terminal · tab 3.
  • The empty-query rule is the same: one row per Terminal window, the other tabs once you type. Old console windows (conhost) have no tabs and stay window rows.
  • Setting: terminal_tabs = true in config.toml (no tray item, since reading Terminal costs little).

4. How it works

4.1 Which windows count as browsers

A window is a browser when both its class and its process are in a fixed table (new src/search/browsers.rs). The process check is what keeps Electron apps out.

Window classProcess (exe)Shown asEngine
Chrome_WidgetWin_1chromeChromeChromium
Chrome_WidgetWin_1msedgeEdgeChromium
Chrome_WidgetWin_1braveBraveChromium
Chrome_WidgetWin_1vivaldiVivaldiChromium
Chrome_WidgetWin_1operaOperaChromium
MozillaWindowClassfirefoxFirefoxGecko
MozillaWindowClasslibrewolf, waterfox, zenLibreWolf, Waterfox, ZenGecko

The Engine column picks how the tab strip is read and which name suffixes are removed. Adding a browser later is one table row plus a test.

4.2 Reading tabs

  • For each browser window, find its tab-strip element and read its TabItem children. A single UI Automation cache request fetches each tab's name and selected state together, in one round trip.
  • Never walk into the page. Web content sits under a Document element, and searching it is slow and makes the browser build accessibility data for every page. The search skips Document subtrees, or follows the exact path to the tab strip that the test run finds.
  • Each tab yields plain data: window handle, cleaned title, raw name, rank among same-named tabs (nth), selected flag and a numeric key. The worker keeps the tab elements from its latest scan under those keys. As with Explorer, no COM object leaves the worker thread.
  • A window whose tab strip can't be found (unknown layout, browser update, timeout) keeps its plain window row, and the log notes it once. Nothing breaks.

4.3 Switching

  1. Restore the window if it is minimized (existing code path).
  2. Find the tab again: first the element kept under the row's key (if its name still matches), then by raw name plus nth, as for Explorer tabs.
  3. Select it with SelectionItemPattern.Select. If that doesn't take, fall back to LegacyIAccessiblePattern.DoDefaultAction, then InvokePattern. The test run shows which one each browser actually uses. QuickSwitch never sends simulated mouse clicks.
  4. Confirm the tab now reports itself as selected, or the window title starts with its title. If a same-named candidate turns out to be wrong, try the next one, as the Explorer code does.
  5. Bring the window to the front with the existing win::activate.

4.4 Threads and timing

Everything runs on the existing STA worker thread (quickswitch-shell), which already owns UI Automation. The UI thread never waits on it.

  • Separate answers: Explorer tabs are sent as soon as they are read (AppCommand::Tabs, unchanged). Browser tabs follow in a new AppCommand::BrowserTabs, so a slow browser never holds up Explorer tabs.
  • Switch requests come first: between browser windows the worker checks its queue, and a Select request runs before the rest of the scan. Pressing Enter early never waits for a long scan.
  • Old scans dropped: answers carry the popup's generation number, and a late answer for an old opening is ignored (existing rule).
  • Busy text: the footer shows “Reading Explorer tabs…”, then “Reading browser tabs…”, then nothing.

5. Step 0: test run

A diagnostic example, examples/browser_tabs_spike.rs, built like the existing examples/uia_spike.rs. It is read-only unless told to switch.

cargo run --example browser_tabs_spike                  # list browser windows, tab strips and tabs
cargo run --example browser_tabs_spike -- --tree 2      # dump the UIA path from window 2 down to its tab strip
cargo run --example browser_tabs_spike -- --select 2 5  # try each switch method on tab 5 of window 2
cargo run --example browser_tabs_spike -- --repeat 5    # time 5 scans in a row (cold, then warm)

For each window it prints: class, process, title, the element path to the tab strip, each tab's raw name, cleaned name, selected flag, runtime ID and supported patterns, and the scan time.

5.1 What the operator runs

Step 1. Open Chrome and Edge (and Firefox and Brave if installed), each with 20+ tabs, including one pinned tab, a tab playing audio, two tabs with the same title, and a collapsed tab group. Use Edge's vertical tabs in one window.

Step 2. Note each browser's memory in Task Manager, then run the plain listing twice (cold, then warm).

Step 3. Run --select on a background tab in each browser, once with the window minimized.

Step 4. Note memory again and paste the output back. For Chrome and Edge, also note what chrome://accessibility or edge://accessibility shows as enabled after the run.

6. Implementation steps

Each step builds and passes cargo fmt --check, cargo clippy --all-targets -- -D warnings and cargo test before the next one.

6.1 Step 1: browser table and name cleanup

  • New src/search/browsers.rs: the table from §4.1, fn browser_of(&WindowInfo) -> Option<&'static BrowserSpec>, and fn clean_tab_name(engine, raw) -> String holding the suffix list the test run found.
  • Tests in tests/browsers.rs: Chrome, Edge and Firefox are recognised, VS Code and Slack (also Chrome_WidgetWin_1) are not, and each real suffix from the test run is removed.

6.2 Step 2: search model

  • src/search/mod.rs: add a BrowserTabInfo record, Target::BrowserTab { window_hwnd, key, name, nth }, Kind::BrowserTab (label “Browser tab”), and browser_tab_item() with MatchOn::Text.
  • Snapshot gets a third range. The order becomes: listed open items (windows, Explorer tabs, each browser window's current tab), then the other browser tabs (searched, not listed for an empty query), then remembered folders. merge_browser_tabs(generation, tabs) replaces each browser window row the same way merge_tabs does. remove_window also drops that window's browser tabs.
  • Recent key: web:<browser>|<hash of lowercase title>, a fixed FNV-1a hash rather than Rust's standard hasher (whose output may change between Rust versions), so page titles are not written to config.toml (§7 D6).
  • Tests: merging, the empty-query rule, a stale generation being ignored, and closed-window removal.

6.3 Step 3: worker split

  • Move the shared UI Automation setup (Uia, timeouts, select_element) out of explorer_tabs.rs into src/search/uia.rs. Move the request loop into src/search/worker.rs. Explorer-specific code stays in explorer_tabs.rs. Behaviour is unchanged.
  • New requests: Request::ScanBrowsers { generation, windows } and Request::SelectBrowserTab { … }. Ordering in the loop: Explorer scan, then pending selects, then browser windows one at a time, checking for selects between them (§4.4).

6.4 Step 4: read and switch browser tabs

  • New src/search/browser_tabs.rs: scan_window() and select(), following §4.2 and §4.3 and the paths and patterns the test run found for each engine.
  • Each window gets its own time budget (UIA transaction timeout plus a wall-clock cap), so one hung browser can't stall the rest.

6.5 Step 5: app wiring

  • src/command.rs: AppCommand::BrowserTabs and AppCommand::BrowserTabSelected.
  • src/app.rs: open() requests a browser scan when the snapshot has browser windows. handle() merges the answer. activate_item() handles Target::BrowserTab (restore if minimized, request select, show “Switching tab…”, and on failure show the error and drop the row).

6.6 Step 6: look and settings

  • src/ui/styles.rs: BADGE_BROWSER = #ec4899. In src/ui/palette.rs, add the badge colour and change the placeholder to “Search windows, tabs, or type ~/folder”.
  • src/config.rs: browser_tabs = true (serde default, so existing config files keep working).
  • src/os/tray.rs: a Search browser tabs checkbox under Start with Windows that turns the setting on or off at once.

6.7 Step 7: docs and release

  • README.md §2 and §2.1, and packaging/README.txt: what is searched, the empty-query rule, what isn't covered, and the tray checkbox.
  • Bump the version to 0.4.0 in Cargo.toml and the installer script. Move this plan to docs/plans/implemented/ once it ships.
  • Demo video: the portfolio repo's demo (~/Projects/personalportfoliosite/demos) can gain a browser-tab scene based on §3.1. That is a separate change made there, not in this repo.

9. Tests and acceptance

9.1 Automated

  • tests/browsers.rs: browser detection and name cleanup (step 1).
  • Snapshot tests: merging, empty-query rule, generation, window removal, recent-key hashing (step 2).
  • Matcher: a browser tab row matches on title and browser name (edge pull).
  • Config: an old config.toml without browser_tabs loads with the feature on.

9.2 Operator checklist

1. Chrome and Edge with 30+ tabs: open the popup. Windows appear at once, and browser tabs follow within about a second.

2. Nothing typed: one row per browser window. Type a word from a background tab and it appears. Press Enter and that tab is shown and its window is in front.

3. Same page in Chrome and Edge: two rows told apart by the grey text. edge … leaves only the Edge row.

4. Minimized browser window: Enter restores it on the right tab.

5. Close a tab while the popup is open, then press Enter on it. The error shows in the footer and the row goes.

6. VS Code, Slack or Teams open: they stay plain Window rows.

7. Press Enter on an Explorer tab right after opening, while browsers are still being read. It switches without waiting.

8. Untick Search browser tabs in the tray. Browser windows go back to plain window rows on the next opening.

9. Firefox, if in scope (D3): steps 1, 2 and 4.

10. Windows Terminal with three tabs, two of them PowerShell: typing powershell shows two rows told apart by tab N. Enter switches to the right one. A conhost cmd window stays a window row.
