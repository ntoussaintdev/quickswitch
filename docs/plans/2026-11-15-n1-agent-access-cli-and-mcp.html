Agent access: qsctl and an MCP server

Let AI agents and scripts use QuickSwitch's index of windows and tabs, and switch to them, without driving the popup.

Created 2026-11-15 · Status: proposed · Target version: 0.5.0

1. Summary

  • The popup already has a UI Automation tree (0.4.2), but an agent can only use it by pressing the hotkey, typing, reading rows and pressing Enter. The index itself is not reachable while the popup is hidden.
  • Part A adds a local, per-user named pipe to the running QuickSwitch and a small console program, qsctl.exe, with search, switch, open and status. Searches use the same snapshot, matcher, type filters and ranking as the popup, without showing it.
  • Part B adds qsctl mcp: a stdio MCP server with three tools (search, switch_to, open) that call Part A. It contains no search logic of its own.
  • Agent access is off by default. A checkbox in Settings → General turns it on. Agent actions leave no history: they don't change recent picks or remembered folders.
  • open refuses programs and shortcuts. Agents can open folders, documents and http(s) addresses, but can't use QuickSwitch to run code.
  • About 30 minutes of agent time (§10), plus the operator's hands-on checks (§8).

2. What exists today

  • Accessibility tree. eframe's accesskit feature is on. The search box is a text field whose active item is the highlighted row (src/ui/palette.rs:229). Rows are list-box options named "title, subtitle, kind" (src/ui/palette.rs:351). This stays as it is: it serves screen readers and agents that drive the screen.
  • Talking to the running copy. src/os/instance.rs has a named mutex and two auto-reset events (Open, Exit). They can signal but can't carry data, so there's nothing to answer a query with.
  • Search lives in the app. QuickSwitchApp::open builds a Snapshot and asks the shell worker to scan Explorer and browser tabs. refresh_results ranks the snapshot against the palette's query. activate_item switches, then hides the popup and updates history. All three are tied to the palette's state (self.visible, pending_tab, palette.status).
  • Switching. win::activate is a plain SetForegroundWindow. It works today because the popup is in the foreground when Enter is pressed. A request from a hidden tray app will often be refused by Windows' foreground lock (§4.5).
  • No console. Release builds of QuickSwitch.exe use the windows subsystem. Output written to stdout from it doesn't reach a terminal, and shells don't wait for it. That's why the client is a separate console program.

3. Decisions

The recommended choice is listed first. The ones marked confirm are yours to change before implementation.

#QuestionChoice
D1How do agents reach the running copy?Named pipe, one JSON request and one JSON reply per connection. Same user and session only.
D2Where do the commands live? confirmA second binary, qsctl.exe, in the console subsystem, shipped next to QuickSwitch.exe in both packages. Alternative: QuickSwitch.exe --list with AttachConsole, which is awkward because shells don't wait for a GUI program and pipes behave differently.
D3Default state confirmOff. Settings → General → "Let AI agents and scripts use QuickSwitch (qsctl, MCP)". The pipe exists only while the box is ticked, and ticking or unticking it takes effect at once.
D4HistoryAgent searches and switches don't change recent or folders in config.toml. Agent scans still note Explorer folders they see, as a popup scan does.
D5What can open open? confirmFolders, files whose extension isn't in PATHEXT or .lnk .url .scf .appref-ms .msi .msc .cpl, and http/https addresses. Everything else is refused with a clear message.

4. Part A: agent channel and qsctl

4.1 Pipe and security

  • Name: \\.\pipe\QuickSwitch.Agent.<user>.<session id>. Pipe names are machine-wide, unlike the Local\ objects, so the session id keeps two signed-in users or two sessions apart.
  • Created with FILE_FLAG_FIRST_PIPE_INSTANCE, so no other process can create the name first, and PIPE_REJECT_REMOTE_CLIENTS.
  • Explicit security descriptor. The default descriptor for a named pipe gives read access to Everyone, which is not acceptable here. Use the SDDL D:P(A;;GA;;;<user SID>)(A;;GA;;;SY), built from the process token. This needs the Win32_Security_Authorization feature of the windows crate. Low-integrity processes (browser sandboxes) are already blocked by the default medium-integrity label.
  • Client check. Before it sends anything, qsctl calls GetNamedPipeServerProcessId and checks that the server is QuickSwitch.exe in the same session.
  • Server thread. A quickswitch-agent thread accepts one connection at a time. It reads one line (at most 64 KB), turns it into AppCommand::Agent { request, reply }, waits up to 8 s for the reply, writes it and disconnects. A second client waits in WaitNamedPipe for up to 2 s. Unticking the setting or exiting stops the thread through a quit event, as in instance.rs.

4.2 Protocol

Requests and replies are single-line JSON (shown wrapped here). v is the protocol version, so the client can say "update QuickSwitch" instead of failing oddly.

→ {"v":1,"op":"search","query":"mail","kind":"browser","limit":10}
← {"ok":true,"complete":true,"items":[
     {"id":"btab:3f2a1c:9d41e07a","kind":"browser_tab","title":"Inbox (3)","subtitle":"Chrome · Work"},
     {"id":"win:1a04b2","kind":"window","title":"Mail","subtitle":"HxOutlook"}]}

→ {"v":1,"op":"switch","id":"btab:3f2a1c:9d41e07a"}
← {"ok":true,"foreground":true}

→ {"v":1,"op":"open","target":"~/Documents/notes"}
← {"ok":true,"opened":"folder","path":"C:\\Users\\…\\Documents\\notes"}

→ {"v":1,"op":"status"}
← {"ok":true,"version":"0.5.0","browser_tabs":true,"terminal_tabs":true}

← {"ok":false,"error":{"code":"gone","message":"That window has closed."}}
  • query takes the same text as the popup, type filters included (term: build). kind is optional and takes the same words as the filters (browser, br, terminal, folder…), so {"query":"mail","kind":"browser"} equals "browser: mail". A path-like query returns the folder suggestions the popup would show.
  • complete is false when an Explorer or browser scan didn't finish within 3 s. The reply then holds what was known, and pending lists the missing sources (["browser_tabs"]).
  • Error codes: bad_request, unknown_id, gone, refused (D5), not_found (open), foreground_denied, busy, timeout, internal.
  • kind values in replies: window, explorer_tab, browser_tab, terminal_tab, folder, file, web. folder and file rows also carry path.

4.3 Result ids

Rows have no ids today. An id is derived from Target, so it needs no table on the server and stays valid while the thing exists:

TargetId
Windowwin:<hwnd hex>
Explorer tabetab:<tab hwnd hex>
Browser or Terminal tabbtab:<window hwnd hex>:<key hex>
Folder, filefolder:<path>, file:<path>
Webweb:<url>

switch looks the id up in the agent snapshot (§4.4), rebuilding it first if it's older than 30 s. Tab ids need the snapshot for their name and position. Window, folder, file and web ids can be acted on from the id alone. A browser tab's key may be stale if the popup rescanned since; the worker then falls back to name and position, as it does for the popup.

4.4 Searching without the popup

  1. Shared ranking. Move the body of refresh_results into a function that takes a snapshot, query, config, engine and ranker and returns Vec<Shown> plus the status and empty hint. The palette calls it and keeps its own status handling. Folder suggestions (path mode) go through the same function.
  2. Agent session. Add an AgentSession to the app with its own Snapshot, generation, pending flags, build time, and the requests waiting for scans. Generations come from the app's one counter, so a worker answer is routed by generation to either the palette or the agent session. The two never share a snapshot.
  3. Scans. A search builds the session snapshot (win::enumerate plus remembered folders), sends the worker the same Scan / ScanBrowsers requests open sends, and answers when both have merged or after 3 s. A snapshot younger than 2 s is reused without rescanning, because agents often search several times in a row.
  4. The popup is never touched. Agent requests don't open, hide or repaint the popup, and don't change its query, selection or status. The Tabs and BrowserTabs handlers drop their self.visible check for agent generations only.

4.5 Switching and the foreground lock

  1. Split activation. Split activate_item into activate_target(item) → Done(Result) | Pending(hwnd) and the palette's wrapper, which remembers the pick, hides the popup or shows the error. The agent path uses activate_target only and keeps its own pending: Option<(hwnd, reply)>. TabSelected and BrowserTabSelected check the agent's pending entry before the palette's.
  2. Let the server take the foreground. qsctl calls AllowSetForegroundWindow(server pid) before a switch or open. This helps when the caller may set the foreground, as a terminal the user just typed in usually can.
  3. Fallback. If SetForegroundWindow is still refused, try once more after the usual workaround: a synthetic Alt press and release with SendInput, which counts as the last input. If that fails too, Windows flashes the taskbar button and the reply is {"ok":true,"foreground":false} with a message. The agent is told; nothing pretends it worked.
  4. Popup open. If the user has the popup open when an agent switches, the popup loses focus and hides itself, as with any other window change. No special handling is needed.

4.6 qsctl commands

CommandDoes
qsctl search [text…] [--kind K] [--limit N] [--json]Prints one row per line: id kind title — subtitle. With --json, prints the reply object.
qsctl switch <id>Switches to the result. Also takes text: qsctl switch "inbox" switches to the top result, and fails with the top 5 listed if two results tie.
qsctl open <path-or-url>Opens a folder (an open Explorer tab is reused), a document or an address (D5). Takes the same path forms as the popup (~/x, %APPDATA%/x, //server/share).
qsctl status [--json]Says whether QuickSwitch is running, its version, and whether agent access is on.
qsctl mcpRuns the MCP server on stdin/stdout (§5).
--no-startDon't start QuickSwitch if it isn't running (D7).

Exit codes: 0 success; 1 the request failed (message on stderr); 2 QuickSwitch isn't running and couldn't be started; 3 agent access is off ("Turn it on in QuickSwitch Settings → General"); 4 usage error. "Running but no pipe" is told apart from "not running" by opening the instance mutex.

4.7 Setting

  • Add agent_access: bool (default false) to Config, with serde default so older files still load.
  • Settings → General gets one checkbox under the tab options: Let AI agents and scripts use QuickSwitch (qsctl, MCP), with the grey note "They can list your window and tab titles and switch between them." Saving starts or stops the pipe thread at once.
  • This is the only screen change: one checkbox row. The plan has no interactive demo for that reason (see §9).

5. Part B: MCP server

5.1 Transport

  • qsctl mcp reads newline-delimited JSON-RPC 2.0 from stdin and writes replies to stdout. Logs go to stderr only.
  • Handled: initialize, notifications/initialized (ignored), ping, tools/list, tools/call. Any other method gets -32601.
  • initialize answers with the client's protocolVersion when it's one we support (2025-06-18, 2025-03-26, 2024-11-05), otherwise the newest. It returns capabilities: {"tools":{}}, serverInfo: {"name":"quickswitch","version":…}, and short instructions: "Search first, then switch by id. Ids expire when the window or tab closes."
  • Each tool call is one pipe request (§4.2). A pipe failure becomes a tool result with isError: true and a message the model can pass on ("Agent access is off in QuickSwitch Settings → General"), not a JSON-RPC error.

5.2 Tools

ToolInputResultAnnotations
searchquery (string, optional), kind (enum: all, window, explorer_tab, browser_tab, terminal_tab, folder), limit (1–50)structuredContent {items, complete} with an outputSchema, plus the same rows as textreadOnlyHint: true, openWorldHint: false
switch_toid (string, from search){foreground} and a one-line messagereadOnlyHint: false, destructiveHint: false, idempotentHint: true

Each tool's description says what it's for in one or two sentences, for example "Find open windows, File Explorer tabs, browser tabs and Windows Terminal tabs on this PC by title". The model picks tools by these descriptions.

Portable users point at qsctl.exe in their unzipped folder. Agents with a shell don't need MCP at all: qsctl search --json is enough.

6. Implementation steps

Dev only. Releasing 0.5.0 is the operator's deploy, after §8.

6.1 Step 1. Setting

src/config.rs: agent_access. src/ui/settings.rs: the checkbox (§4.7), with labelled_by like the others. app.rs::save_general: start or stop the server.

6.2 Step 2. Protocol module

New src/agent/protocol.rs: request and reply types with serde, error codes, id encoding and decoding (§4.3), the kind-word mapping through parse_qualifier, and the D5 extension check. Add serde_json to Cargo.toml. No Win32 or eframe imports, so it's testable on its own.

6.3 Step 3. Pipe server

New src/agent/server.rs: pipe name, security descriptor, accept loop, line read with a size cap, reply wait with a timeout, quit event. Add Win32_Security_Authorization to the windows features. New AppCommand::Agent { request, reply } in src/command.rs.

6.4 Step 4. App refactor and agent session

src/app.rs: the shared ranking function (§4.4 step 1), AgentSession, generation routing in the Tabs and BrowserTabs handlers, and activate_target with agent pending handling (§4.5 step 1). Optionally move the agent part to src/agent/session.rs to keep app.rs from growing past 1,100 lines. The palette's behaviour must stay exactly the same: existing tests must pass unchanged.

6.5 Step 5. Foreground fallback

src/os/windows.rs: activate gets the SendInput retry (§4.5 step 3) and reports whether the window really came forward. The palette path also benefits.

6.6 Step 6. Client and qsctl

New src/agent/client.rs: connect, check the server process, AllowSetForegroundWindow, start QuickSwitch if needed, one request. New src/bin/qsctl.rs (console subsystem): argument parsing (by hand, no clap), text and JSON output, exit codes (§4.6). Cargo.toml: a second [[bin]].

6.7 Step 7. MCP server

New src/agent/mcp.rs: the JSON-RPC loop over a BufRead/Write pair and a Backend trait (pipe client in production, fake in tests); tool schemas and descriptions (§5.2).

6.8 Step 8. Packaging

scripts/package.ps1: copy qsctl.exe into the portable zip and pass it to Inno Setup. packaging/QuickSwitch.iss: install qsctl.exe next to the app, plus an unchecked task "Add qsctl to PATH" (per-user Path, removed on uninstall). Check that CI (.github/workflows/release.yml) builds both binaries.

6.9 Step 9. Docs and version

README: §2.4 (command line) gets qsctl; a new §2.6 "Agents and scripts" covers the setting, commands, MCP setup (§5.3), what agents can and can't do, and the privacy note. §6 code map gets src/agent/. packaging/README.txt: a short section. CHANGELOG.md: a 0.5.0 entry. Cargo.toml: version 0.5.0.

7. Automated tests

  • tests/agent_protocol.rs: request and reply round trips; id encode and decode for every Target, including paths with : and spaces; bad JSON, a missing v or an unknown op gives bad_request; kind words map to the same filter as the popup; the D5 check refuses .exe .bat .ps1 .lnk .url and accepts .pdf .txt and folders; only http/https URLs are accepted.
  • tests/agent_pipe.rs: starts the server in-process with a fake handler, then checks: a client gets the reply; an over-size line is refused; the server stops on quit; a second server with the same name fails (first-instance flag); the pipe's DACL holds only the user and SYSTEM.
  • tests/mcp.rs: drives the JSON-RPC loop with a fake backend. Checks: initialize version negotiation; tools/list matches the schemas; tools/call for each tool; backend errors become isError results; an unknown method gives -32601; notifications get no reply; nothing but JSON goes to stdout.
  • Ranking parity: a test in tests/matcher.rs that the shared ranking function gives the same rows for a fixed snapshot as before the refactor.
  • Run cargo fmt --check, cargo clippy --all-targets and cargo test.

8. Operator testing

The agent doesn't run the app (docs/tips/documentation-management §5). By hand, with a few windows, Explorer tabs, browser tabs and Terminal tabs open:

  1. With agent access off, qsctl status says it's off and exits with 3. Tick the box and it says it's on, with no restart.
  2. Run qsctl search with nothing typed, then qsctl search mail, qsctl search --kind terminal and qsctl search "br: docs". Each gives the same rows the popup would show, while the popup stays hidden.
  3. From a terminal, run qsctl switch <id> for a window, a minimized window, an Explorer tab and a browser tab. Each comes to the front. Note any foreground:false (the §4.5 fallback).
  4. With the popup open, run a search from another terminal. The popup's results and selection don't change.
  5. Run qsctl open ~/Documents and qsctl open https://example.com; both open. Run qsctl open C:\Windows\notepad.exe; it's refused.
  6. Exit QuickSwitch, then run qsctl search x. It starts QuickSwitch and answers, unless --no-start is passed.
  7. Add the MCP server to Claude Code (§5.3), then ask "switch to my Terminal tab running the build". It calls search, then switch_to.
  8. Check that recent in config.toml is unchanged after the agent switches (D4).
  9. Install the 0.5.0 setup over 0.4.3: qsctl.exe is installed, the PATH task works, and uninstall removes both.

9. Risks and open points

  • Foreground lock. This is the main unknown. The AllowSetForegroundWindow plus SendInput combination usually works, but Windows may still refuse when the agent runs from a process the user hasn't touched recently (a scheduled job, Claude Desktop in the background). The result then says so honestly. Operator step 3 settles it.
  • Scan time. Browser tab scans through UI Automation can take about a second with many windows. Partial replies (complete:false) keep agents from hanging; the 2 s snapshot reuse cuts repeat cost.
  • Privacy. With access on, window and tab titles go to whichever model the agent uses. The setting's note and the README say so. That's why it is off by default.
  • Second unsigned exe. SmartScreen or Defender may warn about qsctl.exe separately. Same situation as QuickSwitch.exe today.
  • MCP version drift. Supporting the three dated versions covers current clients. Newer ones negotiate down.
  • No demo. The only screen change is one checkbox row (§4.7), so the plan has no interactive demo. Say if you want one anyway.
