Agent worktree base commit

1. Summary

  • A subagent started with isolation: "worktree" gets its own git worktree, but that worktree is not guaranteed to start from your local HEAD. It can start from origin/<default branch> instead.
  • When your local branch is ahead of the remote, such an agent works on old code and reads old instruction files (CLAUDE.md, AGENTS.md, docs), without saying so.
  • Make step 0 of every worktree agent's prompt a fast-forward to the commit you expect (§4). Or create the worktree yourself from that commit.
  • Reusing a worktree you already have, fast-forwarded, also skips a fresh dependency install.

2. What happens

  • The Agent tool creates the worktree under .claude/worktrees/agent-<id>, on a branch named worktree-agent-<id>.
  • In one session (2026-10-23), the local branch was ahead of origin/main. Some agents launched in the same session got worktrees on origin/main; others got local HEAD. Nothing in the launch result said which.
  • The agents on origin/main read instruction files and docs that had since changed, and worked on code without the newer commits. The time went on spotting this and telling each of them to fast-forward before carrying on.

3. How to check a worktree's base

  1. Note the commit the agent should start from, in your own checkout: 
    git rev-parse HEAD
  2. Check that the agent's worktree contains it (exit code 0 means yes): 
    git -C .claude/worktrees/agent-<id> merge-base --is-ancestor <sha> HEAD
  3. Or list every worktree with the commit it is on: 
    git worktree list

4. How to prevent it

4.1 Fast-forward as step 0

  1. Take the expected commit: git rev-parse HEAD.
  2. Put this first in the prompt of every agent started with isolation: "worktree": 
    Step 0: run `git merge --ff-only <sha>` in your worktree before anything else.
If it is not a fast-forward, stop and report; do not merge or rebase.
  3. Ask the agent to report the commit it started from, so its report can be checked against §3.

4.2 Or create the worktree yourself

  1. Create it from the exact commit: 
    git worktree add .claude/worktrees/<name> -b <branch> <sha>
  2. Start the agent without isolation and give it the worktree's absolute path as its only working directory.

4.3 Reuse a worktree for follow-up work

  1. Once an agent's branch is merged, keep its worktree instead of asking for a new one.
  2. For the next task, fast-forward it to the current branch (git -C <worktree> merge --ff-only <sha>) and give the next agent its path.
  3. Its dependencies are already installed, which saves a fresh npm install (or equivalent) per agent.
