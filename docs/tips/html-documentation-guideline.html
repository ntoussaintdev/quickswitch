HTML documentation guideline

1. Summary

  • The first section of a document is a brief summary.
  • A table of contents sits at the side and follows the scrolling.
  • Sections and steps carry visible numbers, so a place in the document can be referred to by number.
  • The page is dark, with a light mode toggle at the top.
  • Demos, animations and diagrams are included when the user asks for them.
  • A demo goes wide when it needs the room, and stays wide on a small screen.
  • While wide blocks hide the table of contents, a small contents button at the far left of the window brings it back on demand.
  • Every table has a sticky header, so its column names stay in view while its rows scroll.

2. Table of contents

  • It sits at the side of the page and stays in view while the page scrolls.
  • It lists the sections and marks the one being read.
  • Every section heading it links to has an id.
nav.doc-toc { position: sticky; top: 24px; align-self: start; }
const links = Array.from(document.querySelectorAll('nav.doc-toc a'));
const byId = new Map(links.map((a) => [a.getAttribute('href').slice(1), a]));
const io = new IntersectionObserver((entries) => {
  entries.forEach((e) => {
    if (!e.isIntersecting) return;
    links.forEach((l) => l.classList.toggle('is-current', l === byId.get(e.target.id)));
  });
}, { rootMargin: '-15% 0px -75% 0px' });
byId.forEach((_, id) => io.observe(document.getElementById(id)));

3. Section and step numbers

Show section and step numbers in the text itself, so a place in the document can be referred to by number ("§3.2", "step 4").

  • Number the headings (1., 1.1, 2.) and put the same numbers in the table of contents.
  • Number the steps of any procedure or implementation sequence. Don't use plain bullets for steps.
  • The number must be visible to the reader, not only present as an id or produced by a CSS counter that a copy and paste would drop.
<h2 id="numbers">3. Section and step numbers</h2>
<h3>3.1 Headings</h3>

4. Dark mode and the toggle

  • The page opens in dark mode.
  • A toggle at the top of the page switches to light mode and back.
  • Colours are CSS variables, so the toggle only swaps one set for the other.
:root                     { --bg: #12161c; --fg: #e3e8ef; }
:root[data-theme="light"] { --bg: #ffffff; --fg: #1c2430; }
button.addEventListener('click', () => {
  const root = document.documentElement;
  if (root.dataset.theme === 'light') delete root.dataset.theme;
  else root.dataset.theme = 'light';
});

5. Demos and diagrams

  • JavaScript, CSS or SVG demos, animations and diagrams go in when the user asks for them.
  • They are written into the document itself.

6. Wide demos

Examples and demos must stay readable. A demo squeezed into the text column ends up with small labels, scaled-down SVGs or a cramped layout.

6.1 The rule

  • Prose stays in the normal reading column.
  • When an example or demo needs more room, that one block breaks out into a wide landscape format.
  • The normal column returns straight after the block.
  • Only the blocks that need the width go wide. Don't widen the whole page.
  • The goal is to preserve text and element size. Give the demo more width; don't scale it down to fit.
  • On a small screen the demo stays wide. It does not shrink to the screen. The reader scrolls it sideways.
  • While a wide block is on screen, the table of contents is hidden, so the block can use the space it occupies. It comes back once the block has scrolled away.
  • While the contents are hidden, a small round contents button floats at the far left of the window, where the contents normally are. A click opens them in a panel beside it (§6.4). A page made mostly of wide blocks would otherwise have no contents most of the time.

6.2 How

Mark the block with a class. It grows left over the space of the table of contents and right to the edge of the layout. An inner element carries the width the demo needs.

<p>Text in the normal column.</p>

<figure class="doc-wide">
  <div class="doc-wide-in">
    <!-- wide demo / example -->
  </div>
</figure>

<p>Back in the normal column.</p>
.doc-layout      { --toc-w: 220px; --toc-gap: 44px;
                   grid-template-columns: var(--toc-w) minmax(0, 1fr); gap: var(--toc-gap); }
main > *         { max-width: 780px; }                   /* the reading column */
main > .doc-wide { max-width: none; overflow-x: auto;    /* the block leaves it… */
                   margin-left: calc(-1 * (var(--toc-w) + var(--toc-gap))); }  /* …and takes the contents' space */
.doc-wide-in     { min-width: 1100px; }                  /* as wide as the demo needs */

nav.doc-toc           { transition: opacity .2s, visibility .2s; }
nav.doc-toc.is-hidden { opacity: 0; visibility: hidden; }
const toc = document.querySelector('nav.doc-toc');
const onScreen = new Set();
const io = new IntersectionObserver((entries) => {
  entries.forEach((e) => { if (e.isIntersecting) onScreen.add(e.target); else onScreen.delete(e.target); });
  toc.classList.toggle('is-hidden', onScreen.size > 0);
});
document.querySelectorAll('.doc-wide').forEach((el) => io.observe(el));

Where the table of contents is not at the side (a narrow screen, where it sits above the text), the block has no left margin and the contents are not hidden.

6.3 Things to check

  • Table of contents. The wide block must never sit on top of visible contents. They are hidden for as long as any part of a wide block is on screen.
  • Clipping. No ancestor of the block may have overflow: hidden or a max-width that clips it.
  • Small screens. The demo keeps its width and scrolls sideways inside its own block. The text around it does not move.
  • Fixed sizes inside. Set font sizes and control sizes in the demo in px or rem, so the extra width goes to layout and nothing is scaled up or down. For an SVG, widen the viewBox to suit the landscape shape; don't stretch a narrow one.
  • Class name. Prefix it (doc-wide) so it can't collide with a global rule such as .wide.
  • Margin shorthand. A later rule of the same weight that sets margin on the block, such as figure.doc-wide { margin: 18px 0 22px; }, resets the negative left margin, and the block quietly stops breaking out: it stays in the column and only runs over to the right. Set margin-top and margin-bottom instead.

6.4 The contents button

  1. When it shows. Only while the side contents are hidden by a wide block (nav.doc-toc.is-hidden), and never where the contents sit above the text (a narrow screen), since they are not hidden there.
  2. Where. Fixed at the far left of the window, centred vertically, on the side the contents normally occupy. It is small (about 34 px) and round, so it covers almost nothing of a wide block.
  3. What a click does. It opens a panel beside the button with the same links as the side contents, the section being read marked. Build the panel from the side contents each time it opens, so the mark is current.
  4. Closing. Choosing a link, pressing Escape or clicking outside the panel closes it. Moving back to a place where the contents show again hides the button and closes the panel.
  5. Accessible. A real <button> with aria-label="Contents" and aria-expanded; focus returns to it on Escape.
.toc-btn   { position: fixed; left: 10px; top: 50%; transform: translateY(-50%); z-index: 50;
             width: 34px; height: 34px; border-radius: 50%; border: 1px solid var(--line);
             background: var(--soft); color: var(--muted); cursor: pointer; }
.toc-panel { position: fixed; left: 52px; top: 50%; transform: translateY(-50%); z-index: 51;
             width: min(300px, calc(100vw - 80px)); max-height: 80vh; overflow: auto;
             background: var(--soft); border: 1px solid var(--line); border-radius: 8px; padding: 10px 8px; }
.toc-btn[hidden], .toc-panel[hidden] { display: none; }   /* a display rule would otherwise beat [hidden] */
const nav = document.querySelector('nav.doc-toc');
const narrow = matchMedia('(max-width: 900px)');
const btn = Object.assign(document.createElement('button'), { type: 'button', className: 'toc-btn', textContent: '\u2630', hidden: true });
btn.setAttribute('aria-label', 'Contents'); btn.setAttribute('aria-expanded', 'false');
const panel = Object.assign(document.createElement('div'), { className: 'toc-panel', hidden: true });
document.body.append(btn, panel);
const close = () => { panel.hidden = true; btn.setAttribute('aria-expanded', 'false'); };
const open = () => {
  panel.replaceChildren(...[...nav.querySelectorAll('a[href^="#"]')].map((a) => a.cloneNode(true)));
  panel.hidden = false; btn.setAttribute('aria-expanded', 'true');
};
const sync = () => { btn.hidden = !(nav.classList.contains('is-hidden') && !narrow.matches); if (btn.hidden) close(); };
btn.addEventListener('click', () => (panel.hidden ? open() : close()));
panel.addEventListener('click', (e) => { if (e.target.closest('a')) close(); });
document.addEventListener('keydown', (e) => { if (e.key === 'Escape' && !panel.hidden) { close(); btn.focus(); } });
document.addEventListener('click', (e) => { if (!panel.hidden && !panel.contains(e.target) && e.target !== btn) close(); });
new MutationObserver(sync).observe(nav, { attributes: true, attributeFilter: ['class'] });
narrow.addEventListener('change', sync);
sync();

7. Tables

7.1 The rule

  • Every table has a sticky header: the row of column names stays at the top of the table while its rows scroll under it. A reader halfway down a long table still knows what each column is.
  • Explain the columns that aren't plain words (abbreviations, statistics, slice names) in the text next to the table.

7.2 How

The header sticks to the top of the window while the page scrolls. So on a normal screen nothing between the table and the page may scroll. On a narrow screen, where the table has to scroll sideways, its wrapper becomes a scrolling box of its own and the header sticks to the top of that box instead.

<div class="doc-table">
  <table>
    <thead><tr><th>…</th></tr></thead>
    <tbody>…</tbody>
  </table>
</div>
.doc-table          { overflow: visible; }                 /* the header sticks to the window */
.doc-table thead th { position: sticky; top: 0; z-index: 2;
                      background: var(--soft); box-shadow: 0 1px 0 var(--line); }
@media (max-width: 900px) {                                /* sideways scrolling: a box of its own */
  .doc-table        { max-height: 80vh; overflow: auto; }
}

7.3 Things to check

  • No scrolling ancestor. A sticky header sticks to its nearest ancestor that scrolls. A wrapper with overflow-x: auto (the usual guard for a wide table) counts as one even though it never scrolls up or down. The header then sticks inside a box that doesn't move, which looks exactly like no sticky header. The same goes for any overflow other than visible (or clip) on the wrapper, the section or the main column. An inner scrolling box only helps for a table taller than the box: a short table in one never sticks while the page scrolls.
  • Opaque header. The header cells need a solid background, or the rows show through them as they scroll past. A border on a sticky cell scrolls away with the table; draw the line under the header with a box-shadow instead.
  • Wide tables. A table with many columns goes wide like a demo (§6). The same wrapper scrolls it sideways on a small screen.
